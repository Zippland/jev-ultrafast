# 实时语音工作台

第一版实测与已知范围见 [验证记录](voice-v1-validation.md)。
后续持续语音和延迟改进见 [体验验证（包含失败）](voice-experience-validation.md)。

入口：`uv run jev-voice` → `http://127.0.0.1:8767/`。麦克风开关与运行状态位于紧凑顶栏。
开始时自动建立本地 ASR、应用发现和执行会话；关闭时停止采集并暂停执行。
再次开始可继续当前上下文。实时转写和 Jev 决策并排展示；可切换历史决策，查看其输入版本、最近输入快照及候选概率。
执行记录区分工具返回与后续可见变化；界面变化不是成功证明，未见变化也不保证没有副作用。
采集配置、当前应用观察和原始事件折叠收起。没有逐句闲聊分类，不将 LISTEN 标记为“闲聊已过滤”。

## 执行链路

1. 浏览器 AudioWorklet 按设备实际采样率持续转换为 16 kHz 单声道 PCM16，每 200 ms 发送一块。
   有顺序号和有界队列；缺帧、重复、上传积压会停止，不丢块继续。持续采集不再因到达 120 秒而自动关闭；ASR 活动音频段最多 45 秒，定稿队列最多 2 段。
2. 独立常驻 Python 子进程加载本地 Qwen3-ASR。Silero VAD 分段，活动段滚动识别，端点定稿。
   同一段携带 `revision/base_revision`；旧候选会被新版替换，历史版本保留在 trace。
   空白的新段不会唤醒决策，已有段被回改为空白则会更新。
3. Jev 首先看到实际运行的应用和实际 Chrome 标签页。`SWITCH_APP` 选择需要读取的应用或标签页，随后该界面的
   真实可操作控件成为选项。原生应用通过公共 MCP 读取 AX；标签页通过 Browser Harness 读取 DOM。
   用户不选择 App / 标签页，也不提供操作计划。
   首次等待真实应用列表，此后在需要刷新且距上次刷新至少 5 秒时后台读取，界面操作不等待列表刷新。
   列表年龄、刷新状态和错误进入 trace；目标执行仍以实际界面重新校验。
4. 复用 Ultrafast 的 `operation_questions` 和 `selected_answers`：一个请求选择操作及该操作的目标，
   只消费选中分支。没有独立的 App 分类题；目标携带 App、标签页和执行通道。状态包含当前操作对象，
   只有当前对象暴露具体控件，其他对象仅作为切换候选。需要字面文字参数时才调用 OpenRouter 文本模型。
   原版填写顺序保持为选择字段 → 生成文字 → 校验新鲜度 → 聚焦并填写；CU 的 `set_value` 直接设置目标字段。
   替换、插入、文字选择、网址和上传路径各自给出参数含义，文本模型不能输出操作、选择器或代码。
   鼠标键、快捷键、选区模式和滚动方向／幅度仍是 Jev 的有限选项，只消费选中操作对应的答案。
   应用内容作为数据传入；模型不能生成选择器、坐标、代码或任意 MCP 参数。
5. 新转写在选择、填字生成或原生新鲜度检查期间到达时，Jev 用二选一判断**精确的待执行动作与文本**是否仍合适。
   代码只处理版本、一致性、停止与资源边界，不用字符串规则解释改口或意图。
6. 派发前校验会话 epoch 和输入版本；真正派发之后先记录返回，再使用工具返回的界面状态或重新读取界面。
   自动路由复用原生操作返回的完整 AX，不额外重读同一结果；下一次操作前仍重新获取租约并校验指纹。
   最终验收使用独立读取，操作返回值本身不等于验收成功。
   当前执行器无法撤销已经派发的调用。结果不确定时暂停并禁止直接恢复，需要用户检查后开始新会话。
7. `LISTEN` 等待下一段或下一个版本，不持续空转调用模型。
   `WAIT` 由 Jev 选择等待当前 App / 标签页变化，短暂等待后重新观察；没有新语音也可继续原任务。执行循环不再按 80 次决策强制结束，每轮检查暂停及输入更新，直到模型选择 LISTEN、用户暂停或出现错误。会话文本仍最多 48000 字或 256 段，达到边界时需新会话；尚未证明无限长任务可持续完成。
   工作台断联超过 20 秒自动暂停；暂停检查不会等待模型请求结束。

路由和执行保持在本仓库：`automatic.py`、`live.py`、`mixed.py`、`relay.py`、`browser.py`。
默认入口采用当前对象的工具加切换选项；CU100 的显式绑定实验仍可同时提供多个界面作对照。
底层能力及当前适配范围见 [工具清单](tool-inventory.md)，不等于所有底层工具都已成为 Jev 选项。
不修改、复制或启动另一个 CU 仓库的实现。`cua-relay serve` 仅作为独立公共 MCP 执行服务。
语音依赖在单独 Python 环境内，外部 Qwen 权重只读使用。该进程不接收 Jev / 文本模型凭据。

## 证据与诊断

每次会话独立目录 `artifacts/voice/<时间-随机ID>/`：

- `events.jsonl`：逐条追加；ASR、输入替换、观察、选择、文本生成、二次判断、工具派发、返回和失败。
- `model.start/end/error`：完整模型请求/结果；`model.http.*` 逐次 HTTP 尝试，避免把重试藏在调用计数里。
- `mcp.*` / `cdp.*`：请求参数、响应和耗时；不记录 Authorization header。
- `source-sha256.json`：服务进程启动时捕获的生产代码和前端哈希；前端也从同一快照提供，避免运行中修改磁盘导致前后端版本混用。ASR 子进程另行上报其启动版本。
- `asr.stderr.log`：本地识别进程诊断。工作台不保存原始音频。

浏览器里看到的事件列表是摘要，下载按钮提供完整 JSONL。一次成功的 MCP 返回或模型 `LISTEN`
都不能替代最终结果检查。真实实验应同时留存目标应用的新 AX / DOM 状态。

离线检查不会调用付费 API：

```bash
uv run ruff check .
uv run pytest
node --check jev_ultrafast/static/app.js
node --check jev_ultrafast/static/voice.js
node --check jev_ultrafast/static/pcm-worklet.js
node --test tests/pcm-worklet.test.cjs
uv build
```

已覆盖的并发边界包括：同段回改、LISTEN 不空转、选择中暂停、原生读取期间的新输入、精确文本重新判断、
结果不确定不重放、断联停止、浏览器第一次输入前的取消、ASR 版本缺口、自动 App / 标签页路由、
16 / 44.1 / 48 kHz 音频在跨帧状态下精确重采样和尾块发送。

## 当前范围

这是可试用的实验入口，不是已通过 100 题的稳定性版本。现有 CU100 冻结用例及之前的失败证据保持独立。
当前发现范围是正在运行的 App 和 HTTP(S) Chrome 标签页；需要控制的原生应用应已打开。
公共 cua-relay 按 App 当前窗口暴露控件，不提供任意原生 window ID 路由；每次动作前校验新的界面指纹。
一个 Jev 目标头超过 255 时明确报错，不静默丢弃控件。目前未实现超大页面目标的分层选择。
语音浏览器适配器也会拒绝原 DOM 快照已报告省略控件的页面。
CU 自由拖拽需要可靠坐标锚点，当前 AX 接口不提供，所以不生成拖拽候选；不会凭空猜测截图坐标。
浏览器的任意 JS/CDP、HTTP 抓取和录制管理没有作为自由生成的模型工具；观察、执行与 trace 由代码封装。
原生任意窗口 ID、iframe/shadow DOM 全覆盖和任意按键组合不属于当前版本。
原生 AX 读取和操作可能各需数秒，不能以 Jev 推理耗时作为端到端延迟。

麦克风输入的真实体验还取决于设备权限、声学环境、ASR 回改质量和模型服务连通性。
代码不会把 ASR 的“稳定前缀”当成已经不会改变的用户意图，也不会用固定关键词判断执行、否定或改口。

### 状态变化后的读取复用（2026-09-21）

桥接层在动作前发现 AX 指纹变化时，拒绝旧动作，并将刚读取的状态一次性用于下一轮选择，
避免异常恢复路径紧接着重复调用 `get_app_state`。下一次派发仍必须重新读取和比对；
没有复用派发授权，没有重试已经派发的动作。离线测试覆盖连续两次外部修改均阻止写入、
快照只消费一次、后续观察再次读取。108 项测试、Ruff、前端语法及构建通过。
该变化只减少每次此类重新选择的一次读取，尚未测量真实端到端耗时改善；已有运行进程须重启才加载。

### OpenRouter文字输出约束

OpenRouter端点使用`response_format: json_schema`，只允许一个`text`字段（字符串或缺失值null），
并设置`provider.require_parameters=true`，避免路由到不支持所需参数的端点。
本地仍要求非空、长度不超过2000的字符串，拒绝说明文字、额外字段或null；不截取JSON、不自动修复、不回退为猜测输入。
其他OpenAI兼容端点保留json_object模式。不支持该Schema的OpenRouter端点会显式失败，需要选择支持的端点。
依据：https://openrouter.ai/docs/guides/features/structured-outputs 。接口接受约束不等于所有服务商保证100%符合，必须保留本地验证。

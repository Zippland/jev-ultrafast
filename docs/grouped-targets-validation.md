# 超过 255 个目标：分组选择与上下文边界

2026-09-22。仅在本项目 bridge 开启分组，不改独立 cua-relay MCP。

## 实现

同一操作超过 255 个观测目标时，按原观测顺序每 255 个分组，在同一 JEV 请求中提交操作题、目标组题和各组目标题。全部候选保留；只验证并消费选中操作、组和组内目标，其余分支忽略。最多支持 255 组，超出明确报错。原浏览器代理默认保持单层选择。没有基于用户文字的匹配或正则路由。

官方资料说明每道题独立求值，可同时提交推测性问题，应用只消费所需答案： https://docs.typesafe.ai/primitives 。本实现不让组内题依赖同次请求的组选择结果，而是提前提交所有组内题。

## 证据

- 209 项离线测试通过，含组边界、未选分支无效答案忽略、选中组/目标无效时拒绝。Ruff、两个 JS 语法检查、离线构建通过。
- artifacts/grouped-targets-v2：511 个合成点击目标，真实付费模型分别选第 255、256、511 个，三次都正确；单请求耗时 2362、801、553 ms。不包含电脑操作，不是端到端响应延迟。
- 同目录 saved-ax-summary.json：实际失败飞书快照包含 326 个点击目标，分成 255 / 71 两组，所有目标保留。
- 实际飞书请求仍返回 HTTP 400 max_tokens_exceeded；数量上限与上下文预算是两个问题。后续 v3–v7 的压缩实验也未通过，已撤去复杂压缩，保留原始失败证据。不能声称飞书超限问题已经解决。

# CU100 v1：真实 App、混合工具的时序输入测试

这是一套手工调用付费模型、控制真实 macOS App 的实验；不属于离线单元测试，也不包含麦克风或 ASR 推理。

- 计算器、文本编辑、Chrome 浏览器、跨 App 各 25 题，共 100 题。
- 40 题包含多次输入，合计 147 次输入事件。
- 14 题要求不操作；16 题在已执行动作之后补充输入，9 题在选择模型推理中更新输入，5 题在文本生成中更新输入。
- 覆盖运算、文本改写、网页字段/复选框/提交/详情、结果搬运、背景与引用、未说完、显式/隐式改口、ASR 替换、撤回、无关补充、长背景、跨 App 转向与源内容保护。
- 不是全部可能情况的穷举。附件、上传、真实外网导航、认证、购买、文件保存对话框、坐标操作、语音识别准确率均不在 v1 范围。

## 冻结与评分

`suite.json` 已在模型试跑前冻结，SHA-256：

`779d5bb2d542f63e6bd2c64689909fabac09440182bd3379fcfe4b8e63634308`

`build_suite.py` 拒绝覆盖已存在的题集；改变题目需要新版本。完整题目和时序在 `catalog.md`。

预期值只进入初始化和评分器，不进入策略请求。每道题独立初始化；准备动作与被测动作分别记录。策略收到用户截至当时的转写、真实 AX/DOM 观察和实际执行历史，不会收到未来语音、预期答案、题目类别或测试脚本编排的操作步骤。

评分采用新读取的原生 AX 加浏览器页面事件日志；不是模型自报 DONE。检查最终内容、未要求操作的 App 不变、输入事件是否全部到达、禁止提前动作的阶段，以及执行/验证错误。只要一项不满足，该题失败。语言表达含混导致的预期争议需在报告中单列，不事后改答案。

## 决策层

`jev_ultrafast/mixed.py` 完全在 Jev 仓库里实现：

1. 通过独立 CU MCP 获取绑定窗口的 AX 候选，通过现有 Browser Harness 获取同一 Chrome 标签页的 DOM 候选。
2. 一次 Jev 请求选择操作，并预测各操作的兼容目标；目标携带 App 和执行通道，只消费选中操作的目标。
3. Chrome 同时提供 CU 和 Browser Use 候选，目标选择也确定了执行通道。按题目 ID 固定随机化候选通道排列，不强制配额或切换次数。
4. TYPE_TEXT 才调用文本模型，填入的是模型生成值。生成期间有新增语音时，用 Jev 判断具体候选是否仍有效。
5. 保留原有观察新鲜度检查与一次性派发语义。UI 检查拒绝过期动作时重新观察；不重放已经派发或结果不确定的动作。

CU MCP 仓库、进程和协议实现均未修改。两个后端仅在桥接层汇合。实验只绑定三个确定的测试窗口；不操作用户原有的文本编辑文档或其他 Chrome 窗口。

当前默认原生通道为 `cua-relay`，通过其公开 stdio MCP 调用本机官方 Computer Use runtime。
`jev_ultrafast/relay.py` 只在本仓库适配协议：解析工具返回的 AX 角色、索引和属性，不解析用户意图。
官方接口只支持 App 当前关键窗口，因此每次观察都核对 App、窗口标题；文本编辑额外核对测试文件 URL。
每个动作前重新读取状态、比较完整规范化观察，再消费 relay 的一次动作租约。
它没有原后端的显式窗口 ID 与 observation ID 接口；窗口切换会导致停止，不会猜测新窗口或切到用户文档。
这是一版针对已绑定实验窗口的适配，还不是通用窗口发现或路由。

候选范围使用真实观察与支持的操作，单个目标问题超过 255 个选项就明确报错。当前省略通用上下文菜单与无名称的窗口装饰按钮，不通过用户话语的关键词或正则生成决策。

## 运行与证据

先在本机建立三个测试窗口，并把实际 ID 保存到 `artifacts/cu100/windows.json`。Chrome 中的实验页为 `http://127.0.0.1:8770/`；Browser Harness 与 CU 必须指向同一个已验证标签页/窗口。

```bash
uv run python benchmarks/cu100/server.py
uv run python benchmarks/cu100/run.py --run-name <新的运行名称> --backend cua-relay --case-seconds 300
# 之后需要独立 CU 对照时再明确选择：--backend codex-cu
```

模型固定为 `jev-1.13.0`，文字模型使用本地 `.env` 已配置的值。密钥不进入日志、不传给 CU 子进程。每次运行保存题集摘要和实际执行源码哈希，不覆盖旧运行。

`cua-relay` 默认命令为 `["cua-relay", "serve"]`，可通过 `CU_RELAY_COMMAND` 的 JSON 数组覆盖。
`codex-cu` 使用原有 `CU_MCP_COMMAND`。切换执行器不修改独立仓库，也不修改 Jev / 文字模型提示词或题集。
不同执行器返回的 AX 结构和可用操作会不同，实际延迟也会改变时序输入到达时机；两轮不是严格控制所有变量的模型 A/B。

官方通道每个 App 保持独立 MCP 连接，只并行读取状态，动作始终串行；每次执行前仍获取该 App 的新观察。
第一次官方通道时序试跑 `relay-v1` 的 C01 已得到 19，但串行读三个 App 导致触及原 100 秒墙钟上限。
完整基线 `relay-v1-full` 因此使用显式的 300 秒单题预算；24 次动作和 40 次决策上限保持冻结值。
该覆盖值保存在 `manifest.json/effective_limits`；没有修改题集、预期结果或模型提示词。

原始记录位于 `artifacts/cu100/<运行名称>/`：

- `manifest.json`：题集、代码哈希、测试窗口和 Chrome target ID。
- `status.json`、`summary.json`：批次状态与逐题结果。
- `<题号>/mcp.jsonl`：带 setup/run/verify 阶段标记的原始 MCP 请求与响应。
- `<题号>/initial.json`、`result.json`：初始状态、输入时序、选择/文本模型请求与结果、实际动作、独立验证及失败原因。

macOS 锁屏时原生 AX 不可用。运行器在题目开始前检测锁屏并等待，发生中途锁屏或初始化失败时终止批次，避免把后续未运行题目统计成模型失败。不会修改锁屏、睡眠或权限设置。

第一次启动 `mixed-v1` 在 C01 第一次点击后遇到锁屏：C01 中断、其余 99 题未实际执行。该启动的原始错误汇总保留，但不能解释为“模型 0/100”；查看同目录 `classification.json` 的修正分类。

`mixed-v1-unlocked` 已完成 66 题，在用户要求切换到 `cua-relay` 后停止；B17 验证阶段被中断，后续题目没有执行。
它作为原后端的部分诊断记录保留，不与官方通道结果拼成一份 100 题成绩。

## 当前生产链路的浏览器子集（2026-09-21）

`uv run python scripts/check_live_browser_cases.py <新输出目录> --ids B01,B02,...`
复用冻结题目和初始网页值，但运行当前Workbench→AutomaticDesktop→LiveSession，使用当前配置模型。
只接受单输入浏览器题；不包含ASR或原生任务初始状态重置，不能当作完整CU100结果。
模型仍可观察所有App及标签页，真实写操作只允许专用实验页：Browser Harness绑定target，CU绑定Chrome内的实验页AXWebArea及当前题号。
保护不解释用户语言；越界选择会失败，不会修改其他窗口。评分包含网页字段/事件及独立DOM观察。

首批v1（artifacts/live-browser/v1）：B01通过；B02/B03在路由阶段直接LISTEN，未填写/勾选，是真实决策失败；
B04选择了Chrome CU通道的正确实验页字段，却被初版测试保护误拦，为harness限制，不能算语义失败。其余题未运行。
修正保护后v2补跑B04：文本服务返回说明文字混入JSON，严格解析拒绝、没有输入，属于真实文本输出协议失败；后续B05/B06未运行。
原始输出包含`JSON OUTPUT`标记而非纯JSON，不能靠抽取末尾对象伪装服务遵守了协议。
两批不得合并成完整100题或17题成绩。下一步需处理不搜索指令被LISTEN及文本服务格式可靠性。

v3补跑B04（加入OpenRouter严格Schema）：文本调用返回合法格式，但本轮JEV选择Chrome地址栏，
而非实验页关键词框，被保护拒绝。该失败属于目标选择，不是上一轮文本协议错误。B05/B06仍未运行。
严格Schema离线重放原始失败请求3次均合法，但json_object对照3次也均合法，因此不能宣称量化故障率改善。
证据：artifacts/addressing/text-schema-v1、artifacts/live-browser/v3。

v5启动时公开工作台活动，0题运行。重新读取确认暂停后启动v6，但B02执行期间用户再次接管，运行自动停止，B03未开始。
v6原始pass=false不代表语义失败，见同目录classification.json；两批不能纳入完成率分母。
运行器现对接管中断使用独立status=interrupted及pass=null，启动前中断写status.json，完整跑完写complete。
这是评分状态修复，未改变模型策略；当前共享候选表改动的真实B02/B03验收仍未完成。

## 当前纯 CU 工作台回归（2026-09-21）

`scripts/check_live_browser_cases.py` 已改为只用公开 cua-relay MCP 操作 Chrome，最终以新 MCP 连接读取 AX，并交叉检查实验页事件 oracle。不再导入 Browser Harness/CDP。需先让 Chrome 的当前窗口停在本套实验页，运行器核对标题后才开始。

```bash
uv run python -m scripts.check_live_browser_cases artifacts/cu100-native-browser-run --ids B01,B02,B03
```

支持冻结 B 组所有输入事件：定时追加、同段 ASR 替换、模型选择/文本生成中补充、已执行控制操作后补充。`after_actions` 统计已返回的任务控件操作，不含新增的 App 发现/激活/等待；这个运行器与历史绑定窗口执行器的计数差异写入 manifest。每段只有最后一次输入标记 final，未来输入不提前暴露给模型。

记录每次输入到达、实际派发边界，评分额外核验全部事件已到达及 `not_before_event` 阶段没有提前修改。首批 v1 使用单句运行器快照；v2 起包含时序回放能力，必须以各目录 runner.py 和 manifest.json 为准。

本运行器仍只覆盖浏览器子集；它不等同完整100题，也不含真实音频、物理麦克风或独立的跨App状态评分。应用目录不被筛选，越出实验页的修改尝试会被阻止并记失败。公开工作台开始录音时停止实验。错误会终止当前批次，未跑到的题不纳入成绩。

### 当前自动路由、纯 Computer Use 的单 App 复测入口

```bash
uv run python -m scripts.check_live_browser_cases artifacts/<新目录> --ids C08,C09,C10,C12,C15
# 同一命令也保留 B01 等浏览器题；一次批次仅接受 C 或 B 一个分组。
```

此入口使用当前 Workbench/LiveSession；不注入预期答案、不限制模型所见应用候选。
外部应用写入被测试守卫拒绝并记失败；操作前仍走生产的观察和语音校验。
计算器初始化由测试器使用实时 AX 控件完成，初始化轨迹与被测执行分开，
结束后通过新 MCP 连接读取显示值；中文按钮名称仅用于初始化夹具，不进入决策策略。
支持按时间、模型阶段及已完成动作数注入冻结输入，包括同段 ASR 回改。

该入口是单 App 的转写回放，不包含声学识别；其结果不能冒充历史混合版本的
完整 100 题结果。目前未做其它 App 内容的全量前后比对，跨 App 保持不变的要求
还需单独验收。原始冻结题集与评分预期均未修改。

### TextEdit 原生转写回放

当前单 App 入口也支持 T01–T25。先创建并打开一份独立测试文本文件，再传入其路径：

```bash
uv run python -m scripts.check_live_browser_cases artifacts/<新目录> --ids T01,T02,T03 \
  --text-document /absolute/path/to/owned-test.txt
```

文件必须已存在且是当前 TextEdit 窗口。预检绑定完整文件 URL 并记录观测到的标题；
每次初始化、模型写入前检查和独立读回都验证文档身份。测试器只读取唯一可写正文，
保留中文、换行和标点原样评分。不是按窗口名猜测文档，也不创建或关闭用户窗口。
初始化通过公开 MCP 的 set_value 完成；预期正文不进入模型策略。
仍须获得独占桌面的时间窗口，目录内 runner.py 与 trace 记录实际执行版本。
